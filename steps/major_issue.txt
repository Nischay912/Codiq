• DIFFICULTY BADGE ISSUE

--------------------------------------------------------------------------------------------------


- What I Had Earlier (Old Code That Broke) ?

<span
  className={`badge badge-lg ${getDifficultyBadgeClass(
    session?.difficulty
  )}`}
>
  {session?.difficulty.slice(0, 1).toUpperCase() +
    session?.difficulty.slice(1) || "Easy"}
</span>

--------------------------------------------------------------------------------------------------

- Why This Code Did NOT Work ?

# Problem 1 – React Initial Render Behavior

- When the component renders for the first time:

sessionData = undefined
session = undefined

--------------------------------------------------------------------------------------------------

- Because useSessionById(id) is async function.

- React ALWAYS renders once before API finishes.

--------------------------------------------------------------------------------------------------

- So on first render:

session = undefined

--------------------------------------------------------------------------------------------------

# Problem 2 – Optional Chaining Misunderstanding

- This line looks safe:

session?.difficulty

--------------------------------------------------------------------------------------------------

But this line is NOT fully safe:

session?.difficulty.slice(0, 1)

--------------------------------------------------------------------------------------------------

Because JavaScript evaluates like this:

(session?.difficulty).slice(0, 1)

--------------------------------------------------------------------------------------------------

If session is undefined:

session?.difficulty → undefined

--------------------------------------------------------------------------------------------------

Now it becomes:

undefined.slice(0, 1)

--------------------------------------------------------------------------------------------------

CRASH:

Cannot read properties of undefined (reading 'slice')

--------------------------------------------------------------------------------------------------

Optional chaining protects only:

session?.difficulty

--------------------------------------------------------------------------------------------------

It does NOT protect:

undefined.slice()

--------------------------------------------------------------------------------------------------

# Problem 3 – Utility Function Risk

This also runs:

getDifficultyBadgeClass(session?.difficulty)

--------------------------------------------------------------------------------------------------

If inside that function you had something like:

difficulty.toLowerCase()

--------------------------------------------------------------------------------------------------

Then when difficulty is undefined:

undefined.toLowerCase()

--------------------------------------------------------------------------------------------------

Another crash.

--------------------------------------------------------------------------------------------------

Why the new Code Worked?

Most likely:

- Backend schema guarantees difficulty always exists.

- Session never renders UI before data is ready.

- Their utility function doesn’t call string methods.

- They rely on schema default like:

difficulty: {
  type: String,
  enum: ["easy", "medium", "hard"],
  default: "easy"
}

--------------------------------------------------------------------------------------------------

So difficulty is NEVER undefined once session exists.

--------------------------------------------------------------------------------------------------

• New Code (Inline Fallback)

<span
  className={`badge badge-lg ${getDifficultyBadgeClass(
    session?.difficulty || "easy"
  )}`}
>
  {(session?.difficulty || "easy")
    .slice(0, 1)
    .toUpperCase() +
    (session?.difficulty || "easy").slice(1)}
</span>

--------------------------------------------------------------------------------------------------

- Why This New Code Works

Instead of using:

session?.difficulty

--------------------------------------------------------------------------------------------------

We now use:

session?.difficulty || "easy"

--------------------------------------------------------------------------------------------------

What Happens Now During First Render?

First render:

session = undefined

So:

session?.difficulty → undefined

--------------------------------------------------------------------------------------------------

Then:

undefined || "easy"

Which becomes:

"easy"

--------------------------------------------------------------------------------------------------

So now:

"easy".slice(0, 1)

--------------------------------------------------------------------------------------------------

This is SAFE.

No crash.

--------------------------------------------------------------------------------------------------

- What Happens After Data Loads?

After API returns:

session.difficulty = "medium"

--------------------------------------------------------------------------------------------------

So:

session?.difficulty || "easy"

Becomes:

"medium" again as the 1st choice is session?.difficulty and if thats undefined then only "easy" so since now session?.difficulty is fetched clearly and is no longer undefined, so it shows that difficulty there and not just "easy" there, thus here below.

--------------------------------------------------------------------------------------------------

Everything works normally.

--------------------------------------------------------------------------------------------------

- What Was The Actual Core Issue?

--------------------------------------------------------------------------------------------------


The real issue that came to me there was:

- Calling string methods on a possibly undefined value during React’s first render.

--------------------------------------------------------------------------------------------------

React rendering sequence:

- Component renders with undefined session.

- JSX tries to evaluate string methods.

- Undefined does not have .slice().

- Crash occurs.

--------------------------------------------------------------------------------------------------

- Why New Code Fixes It

Because now:

(session?.difficulty || "easy")

ALWAYS returns a STRING.

--------------------------------------------------------------------------------------------------

So string methods are always safe.

So now there are no dependency on:

- Backend timing

- API speed

- React render order

- Schema defaults

--------------------------------------------------------------------------------------------------

- Important JavaScript Rule Learned

Optional chaining:

obj?.prop

--------------------------------------------------------------------------------------------------

ONLY protects access to prop.

It does NOT protect:

obj?.prop.method()

--------------------------------------------------------------------------------------------------

To protect fully you need either:

obj?.prop?.method()

--------------------------------------------------------------------------------------------------

OR provide fallback:

(obj?.prop || "default").method()

--------------------------------------------------------------------------------------------------

Final Conclusion -

--------------------------------------------------------------------------------------------------

Old version failed because:

- React rendered before API data arrived.

- session was undefined.

- String methods were called on undefined.

- Optional chaining was misunderstood.

--------------------------------------------------------------------------------------------------

New version works because:

- Fallback value guarantees string.

- String methods are always safe.

- No crash during initial render.

- Code remains clean and inline like teacher’s.
